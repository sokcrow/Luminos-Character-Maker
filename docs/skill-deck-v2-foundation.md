# Skill Deck V2 — foundation (2026-10-25)

This is a **Unit skill deck** contract shared by players, allied NPCs and hostile NPCs. It does not replace Spell Loadouts or the CombatAction effect pipeline.

- Ten **points** exactly to save/equip a combat-ready V2 deck for any Unit.
- One point per Tier I card, two per Tier II card, three per Tier III card.
- Per-skill copy limits: Tier I ≤3, Tier II ≤2.
- **Tier III: one card total per deck**, including different Tier III skills.
- Each saved copy is an independent `{entryId,skillId,tier}` card.
- Five named player presets remain supported. The selected preset is authoritative in `characterBuild.skillDeck` and `skillDeck`, mirrored in `skillSlotIds`, `skillIds`, `equippedSkillIndex`.
- Save validates the actual learned/assigned/granted Skill catalog; defensive/off-deck skills do not consume card slots.
- `js/skill-deck-rules-v2.js` contains the shared UI/validation contract.
- `js/combat-skill-loadout-074.js` and deployment read V2 entries first and retain legacy 3/2/1 decoding.
- `js/deckEngine.js` accepts `options.deckEntries` for V2 and draws independent copies; legacy 12-card calls retain the old behavior until migrated.
- `js/combat-v073-deck.js` selects V2 only for the canonical mode. Equipment-mode overrides continue using the preexisting deck path.
- A V2 deck cannot silently fall back to autogenerated Tier copies when validation fails.
- Live Combat initializes the same independent two-card hands for `player`, `remote` and `ai`, regardless of faction. The real automatic planner scores only drawn offensive Skills plus permanent/off-deck options, preserving each source Slot and `drawId`.
- Player and AI plans pass the same card validation before sealing. Planning does not consume a card; execution marks it used, including the newest-card acceleration rule.
- Compact checkpoints retain per-Unit/mode hands and RNG. Recovery restores omitted empty RTDB piles; an older UI round cannot rotate a newer checkpoint backwards. Reserves keep their decks without drawing until they return.
- Canonical NPC deployment reads V2 before legacy `action_slots`/indexes; locally resolved NPC Skills are available to the same live kit adapter. An explicitly empty V2 remains empty after RTDB drops its empty array.
- Existing tiered NPC lists retain their authored Skills/copies, including lists larger than twelve cards, and now draw per Slot. They are not silently converted into a ten-point selection. Untiered legacy NPC actions retain compatibility until authored with tiers; invalid explicit V2 never unlocks them.
- Spells, class powers, equipment grants, defenses, and Quick/Free actions are still separate action sources, with their own costs.

## Local verification

`tests/universal-unit-decks-smoke.mjs` exercises player/remote/allied AI/hostile AI, the actual live automatic selector, authoritative card validation, deployment, compact-state recovery, stale rounds, slot loss/gain and reserves. Existing V2, legacy engine, equipment-mode, loadout and hotfix regressions are also run locally. The shipped Combat bundle is rebuilt and integrity-checked. This runtime-only extension adds no UI; it does not claim a live Firebase session or device-browser visual validation.

## Next phases (separate PRs)

1. Unify player/NPC skill and spell capability resolution into one Unit-owned source; avoid three competing combat lists.
2. Route *all* spells, skill statuses, resources, saves, coins and area effects through one server-authoritative Combat Action effect pipeline.
3. Extend the standalone legacy GOAP/CombatAction viewer bridge to use the same legal per-Slot candidates as the active live Combat planner.
4. End-to-end RTDB and Viewer/DM/Player tests, including mobile viewport checks (360×800, 390×844, 844×390, 768×1024, 1280×720, 1920×1080). This foundational PR includes responsive CSS but does **not** claim device-browser visual validation.

Legacy decks remain readable and are upgraded to schemaVersion 2 only when saved from the manager. No mass RTDB migration is performed.
